LLM = codex CLI(ChatGPT 구독) 또는 claude CLI(Claude 구독) — API 토큰 과금이 아니라 구독 사용량 한도를 소모한다. 한도 초과 시 "레이트리밋" 에러로 표면화.

① 전사 (stage_transcribe) — 전부 로컬, 비용 0

  • two_pass(기본 on): small 모델 러프 스캔만 (3.6시간 영상 실측 95초). 구간 선정용이지 최종 자막용이 아니다 — 최종 대사는 ②의 정밀 재전사가 만든다.
  • 결과: {품번}_전사.json/.srt + 대사 밀도 경보(10분당 1줄 미만 = 본편형 의심)
  • ★ 배치 전사(BatchedInferencePipeline) 금지 — 세그먼트가 뭉개져 타임스탬프 파괴

② AI 처리 (stage_ai) — 실행 순서

순서단계비용설명
1메타 조회무료우분투 meta_api → 제목·배우·레이블
2노출지도 (NN 전체 스캔)무료 노출 구간 대사를 전사에서 미리 삭제 후 LLM에 전달 — 금지구간 목록을 프롬프트에 넣는 것보다 토큰 절약+확실. ⓪클린본 또는 ⚡ 순차 클린 완주 영상(.clean 마커)이면 생략 — 이미 3중 필터로 잘라낸 영상을 또 훑지 않는다
3💰 호출 A — map-reduce 블록 요약0~N회 전사 25,000자 초과 시만. 20분 블록별 "줄거리+핵심 대사 후보 12줄". 2시간 ≈ 6회. 블록 실패 시 앞 12줄 폴백(진행은 계속)
4💰 호출 B — 메인 선정항상 1회 메타+후보(또는 전사 통짜)+목표길이+줄거리 힌트 → keep+내레이션+요약+별점 JSON. reasoning high, 1~3분. 입력 ≤25K자 고정.
★2-pass면 한국어 대사는 출력하지 않는다 — 어차피 호출 C가 정밀본으로 교체하므로 러프 번역은 100% 폐기됐다. 대신 "일본어 자막의 시각이 곧 대사 시각이니 내레이션을 그 사이 빈 구간에 배치하라"고 지시 → 대사-내레이션 겹침 금지(고몽형의 핵심)는 유지
5대사 가드 (_guard_keep)무료 대사 0줄 keep 자동 제외(노출 의심). 전부 걸리면 원본 유지=검수行
6정밀 재전사 + 💰 호출 C0~1회 two_pass일 때. keep 구간(1~3분)만 large-v3 재전사(로컬, 100s=34s) → prompt_dialogue_fix가 최종 한국어 대사자막을 생성(호출 B가 안 만드므로 이게 유일한 대사 소스). keep 대사만 보내니 아주 작음.
정밀 전사 실패/0줄이면 러프 전사의 keep 구간 줄로 대체 실행 → 대사자막이 비는 일은 없음(품질만 러프로 후퇴)
7비주얼 노출가드무료노출지도로 keep에서 노출만 도려냄(subtract)
8컷(NVENC)+plan.json+파생물 무효화무료 새 컷 생성 시 이전 컨셉의 voiced/subbed/TTS 조각 자동 삭제

비용 요약

호출횟수프롬프트 크기발생 조건
A. 블록 요약0~6회소 (블록 대사만)전사 25K자 초과
B. 메인 선정1회대 (≤25K자 고정)항상
C. 대사 교체0~1회소 (keep 대사만)two_pass on
선컷된 짧은 영상: 총 2회(B+C) / 2시간 통짜: 약 8회

★ 3중 필터 선컷 = LLM 비용 절감

⚡ 순차 자동 클린(2️⃣→3️⃣→1️⃣)으로 123분 → 수십 분으로 줄인 뒤 ①②를 돌리면:
  1. 전사가 짧아져 25K자 미만 → map-reduce 호출들(A) 통째로 생략
  2. 클린본이라 노출지도 스캔(2번)도 생략
  3. 메인 호출(B) 입력도 작아짐
→ 사실상 LLM 호출 8회 → 2회. 3중_노출필터 참고.

함정 (기존 확정 사항)

  • 프롬프트는 반드시 stdin — argv로 넘기면 본문이 잘려 "자막을 보내달라"는 헛응답(거부로 오인)

  • 빈 응답 시 stderr에서 401(로그인)/429(레이트리밋)을 구분해 에러 표면화
