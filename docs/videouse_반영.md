# video-use 분석 반영 — 무엇을 넣었고, 무엇을 안 넣었나

> 2026-07-13. `browser-use/video-use`(16.7k★, MIT)의 Hard Rules를 우리 코드에 대조해
> **실측으로 확인된 결함만** 반영. 커밋 `3b95266`.
> 문서의 근거 일부는 우리 현실과 달랐다(예: "cut_video가 `-c copy`" → 실제로는 세그먼트별
> NVENC 재인코딩) — 그러나 **"페이드가 전무하다"는 결론은 정확**했고 실측으로 팝을 확인했다.

## ① 컷 경계 30ms 오디오 페이드 ✅ 적용

**실측 A/B** (step2_stt.mp4의 RMS 최대 지점에서 컷 → 팝이 날 조건):

| 컷 경계 | 페이드 없음 | 30ms 페이드 |
|---|---|---|
| 1번 | **60.8%/ms 급락** (= 팝) | 33.9%/ms |
| 2번 | 27.7%/ms | **9.5~15.7%/ms** |

- `cut_video`: 세그먼트마다 `afade` in/out
- `cut_video_smart`: **★keep '경계'에만** — 조각마다 넣으면 keep 내부 GOP 경계에서
  문장 한가운데 소리가 꺼진다(이게 함정)
- `cut_video_copy`: 비디오는 무손실 유지, **오디오만** AAC 재인코딩해 페이드(수 초)

## ② 대사 경계 스냅 + 패딩 ✅ 적용

`common.snap_keep_to_lines` — LLM keep 경계가 말 중간이면 전사 줄 경계로 스냅
(max_snap 1.5s 이내) + 앞뒤 150ms 패딩(타임스탬프 드리프트 흡수).

- **★과도 축소 가드**: 긴 대사 줄이 양 경계에 걸리면 양쪽 다 '버리는' 쪽으로 스냅돼
  4.0s keep이 0.5s로 뭉텅 사라진다(실측) → **절반 이상 줄면 스냅 포기**, 원본 경계 사용.
- 적용 위치가 중요: **정밀 재전사 앞**(정밀 전사·대사가 최종 keep과 일치하도록),
  **노출 가드 앞**(패딩이 방금 도려낸 노출을 되살리면 안 되므로 노출 가드가 마지막).
- config: `snap_cuts`(기본 on), `cut_pad`(기본 0.15)

## ③ self-eval — 렌더 결과 자동 검사 ✅ 적용

`server/core/selfeval.py`, ⑥굽기 직후 실행 → `{품번}_검사.json` + 로그. **판정만 하고
고치지 않는다**(결함을 알려주고 사람이 결정).

| 검사 | 방법 |
|---|---|
| 팝 | 접합점에서 소리가 1ms 만에 45% 이상 급락하는가 |
| 정지 화면 | `freezedetect` |
| 무음 | `silencedetect` |
| 자막 누락 | 자막이 영상의 30% 미만을 덮으면 경고 |

**★핵심 실측 두 가지** (이걸 모르면 검출기가 헛돈다):
1. 세그먼트를 각각 AAC로 인코딩해 concat하면 **오디오 접합점이 '누적 영상 길이'보다
   세그먼트당 ~30ms씩 누적으로 밀린다**(측정: +28ms, +63ms) → 계산한 경계 시각에서 재면
   접합점을 통째로 빗나간다. **넓은 창에서 엔벨로프 최저점**을 찾아야 진짜 접합점이다.
2. AAC 프라이밍 때문에 **페이드가 없어도 접합점 자체는 무음**이 된다 → '골짜기 유무'로는
   판정 불가. 팝을 만드는 건 그 무음으로 **들어가는 속도**다.

검증: 페이드 없는 컷 → 팝 검출 / cut_video·smart·copy(페이드 적용) → 전부 통과.

## ④ 전사 캐시 소스 지문 ✅ 적용

같은 품번에 **다른 영상**을 넣으면 옛 전사를 물려받던 문제. state에 `크기:mtime` 기록,
큐가 `steps_status(video=)`로 대조해 다르면 재전사.

## ⑤ plan keep_meta(beat/reason) + 작업로그 ✅ 적용

- 프롬프트에 `keep_meta:[{start,end,beat,reason}]` 추가 — 왜 그 구간을 골랐는지 근거를
  쓰게 하면 선택이 정교해지고 나중에 추적 가능(하이라이트 모드엔 이미 hook/reason 있었음)
- `{품번}_작업로그.md` — 언제 뭘 했고 어떤 근거로 골랐는지 한 줄씩 append(재작업 추적)

## ⚠️ 따라가지 않은 것

- **호스팅 STT(ElevenLabs Scribe)**: video-use의 이유는 ①CPU가 느림 ②필러 정규화.
  우리는 **GPU large-v3** + 일본어 신음 **환청 필터 직접 튜닝**이라 둘 다 해당 없음.
- **heuristic 스코어 함수**: video-use도 "over-engineering, LLM이 더 잘 고른다"며 폐기.

## ✅ 이미 우리가 맞거나 앞선 것

자막을 필터체인 맨 마지막에(Hard Rule 1) · 세그먼트 추출 후 concat(Rule 2) ·
전사 캐시(Rule 9) · GUI+실시간 미리보기 · 큐+리소스 레인 · 파일 존재 기반 자동 재개 ·
원자적 쓰기 · 정확한 구간 더킹 · **3중 노출 필터**(video-use엔 없는 우리 고유 영역)
