# 3중 노출 필터 — 1️⃣ 화면 · 2️⃣ 소리 · 3️⃣ 의미

> 2026-07-13 정리. 수동 모드에서 부적절(노출·정사·애무) 장면을 걸러내는 3종 스캔 시스템.
> 관련 커밋: `07b2dd5`(STT 버블), `b096914`(CLIP), `49d4904`(✓ 표시)

## 왜 3개가 필요한가 — 실제로 뚫린 사건

FNS-235 테스트(2026-07-12~13)에서 **1️⃣NN → 2️⃣STT 두 단계를 다 돌렸는데도
어두운 소파 애무씬 89초가 결과물에 남았다.** 원인:

| 필터 | 보는 것 | 뚫린 이유 |
|---|---|---|
| 1️⃣ NN(NudeNet) | 노출 **부위** | 옷 입은 채 + 어두운 조명 → EXPOSED 검출 0 |
| 2️⃣ STT(구 30초 윈도우) | **대사** 유무 | "動いていい?" 속삭임이 '실대사'로 인정 → 30초 통째 보존. 윈도우 경계에 걸친 무대사 정사 43초도 통과 |

각 필터는 자기 신호만 보기 때문에 **부위도 안 보이고 대사도 있는 장면**(옷 입은 애무)이
구조적 사각지대였다. 그래서 **장면의 의미**를 보는 3️⃣을 추가했다.

## 세 스캔의 원리

### 1️⃣ 화면 — NN 노출 (NudeNet)
- 노출 부위(가슴/성기/항문/둔부 EXPOSED) 직접 검출 + **살 노출 지속** 규칙
  (겨드랑이·배 노출이 20초 윈도우의 30% 이상 = 옷을 벗은 정사 구간)
- 사각: 부위가 가려진 체위, 옷 입은 애무, 어두운 조명
- 함정(반대 방향): 노출 의상으로 **대화**하는 장면을 정사로 오판 → 2️⃣가 되돌림

### 2️⃣ 소리 — 신음·정사 구간 (Whisper small + 대사 버블)
- small 모델 **순차** 전사(배치 금지 — 세그먼트 뭉개져 타임스탬프 파괴)
- **대사 버블 방식**: '내용 있는 대사' 앞뒤 ±pad(기본 5초)만 보호,
  보호 밖 공백이 8초 이상이면 삭제 후보. 영상 시작·끝 경계도 동일 처리
- '내용 있는 대사'가 **아닌** 것(보호 못 함): 신음, 같은 말 반복(やばい×3),
  흥분 상용구뿐인 줄(いいじゃん、やろう), 4자 이하 호명(トミー)
  - 단 이런 약한 발화는 삭제 트리거도 아님 — 주변 진짜 대사 버블 안이면 같이 살아남음
- 대화신은 대사가 촘촘해 버블이 이어지므로 안 잘림 (식사대화 0컷 실측)

### 3️⃣ 의미 — 스킨십·애무 장면 (CLIP zero-shot)
- CLIP이 프레임(2초 간격)과 문장을 대조: "두 사람이 키스한다" 류 7문장 vs
  "파티에서 대화한다" 류 9문장의 유사도 **차이(margin)**
- 이동평균 14초 스무딩 + 임계 0.02 + **14초 이상 지속**해야 검출
  - '지속' 조건이 오탐 방지 핵심: 쓰러진 사람 부축 같은 순간 스파이크는 걸러지고
    애무는 수십 초 이어진다
- 모델: Xenova/clip-vit-base-patch32 ONNX 양자화(~150MB, `models/clip/` 최초 1회
  자동 다운로드). onnxruntime **CPU**로 26fps — torch 불필요, 완전 로컬
- softmax 확률 방식은 실패작이었음(노출 의상 파티 장면까지 끌어올림) — margin 채택

## 사용법

세 버튼은 **순서 무관, 독립적** — 각자 "🎬 작업 대상" 배지에 표시된 영상을 훑어
같은 삭제 구간 목록에 후보를 추가할 뿐이다. 자동으로 자르지 않는다(검토 가능한 자동화).
끝나면 버튼에 **✓ N구간**이 남는다(✓ 0구간 = 돌렸는데 깨끗).

### 플로우 A — 한 번에 (타임라인 안 헷갈림)
1. 원본 로드 → 1️⃣, 2️⃣, 3️⃣ 아무 순서로 실행 (하나 끝나면 다음)
2. 삭제 목록(원본 타임라인 기준으로 전부 병합)을 검수 — 빼거나 추가
3. **① 잘라내기 한 번**으로 끝

### 플로우 B — 순차 (더 빠름: 뒷 스캔의 입력이 점점 짧아짐)
1. 1️⃣ 스캔 → 잘라내기 → 모달의 **"잘라낸 영상으로 계속"** 클릭 (필수!)
2. 2️⃣ 스캔(잘린 영상 기준) → 잘라내기 → "잘라낸 영상으로 계속"
3. 3️⃣ 스캔 → 잘라내기
- 주의: "잘라낸 영상으로 계속"을 안 누르고 모달을 닫으면 작업 대상이 안 바뀐다
  (경고 로그가 뜬다). 각 단계의 삭제 목록은 **그 시점 작업 대상의 타임라인** 기준.

### 옵션
- 2️⃣ 대사 보호: 좁게 ±3 / 표준 ±5 / 넓게 ±8초 — 좁을수록 많이 잘림
- 3️⃣ 민감도: 민감 0.015 / 표준 0.02 / 둔감 0.03 — 낮을수록 많이 잡음
- 3️⃣이 못 잡는 애무가 나오면 민감도를 낮추고, 일상 장면(마사지·옷 갈아입기 등)을
  잡으면 그 장면을 `server/core/intimacy.py`의 PROMPTS_NEUTRAL에 추가

## 속도 (123분 원본 실측)

2026-07-13 실측 (FNS-235 원본 123분, GUI 기본 설정):

| 스캔 | 전체영상(123분) 소요 | 검출 | 비고 |
|---|---|---|---|
| 1️⃣ NN (1초 간격) | **2분 57초** | 11구간 / 117.4분 | CPU ONNX |
| 2️⃣ STT (small 순차) | **1분 25초** | 46구간 / 무대사 95.3분 (대사 268 · 신음 257세그) | GPU |
| 3️⃣ CLIP (2초 간격) | **2분 10초** | 8구간 / 114.9분 | CPU ONNX |

**플로우 비교 (스캔 시간 기준):**

| 플로우 | 총 스캔 시간 | 내역 |
|---|---|---|
| A — 전체영상에 셋 다 | **6분 32초** | 2:57 + 1:25 + 2:10 |
| B — 순차(자르면서) | **약 3분 5초** | ①2:57 → 잘리고 5.6분 남음 → ②4초 → ③4초 |

- 이 작품은 NN이 123분 중 117분을 들어내는 극단 케이스라 순차가 **~2.1배** 빠르다.
  ①에서 덜 잘리는(대화 많은) 작품이면 격차는 줄어든다.
- 순차 플로우는 중간 잘라내기(스마트컷) 시간이 단계마다 추가되지만, 남기는 분량이
  적을수록 잘라내기도 빨라서 체감 차이는 크지 않다.
- 결론: **속도는 B(순차), 타임라인 단순함은 A(한 번에)** — 취향대로. 긴 원본일수록 B 유리.
