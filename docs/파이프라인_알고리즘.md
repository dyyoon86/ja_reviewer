# ja_reviewer 파이프라인 알고리즘

일본 AV 신작 원본(100~225분) → 딸딸기튜브 리뷰 영상(약 2분)까지, 각 섹션이 **무엇을 보고 무엇을 기준으로 판단하는지** 정리한 문서.

숫자는 전부 코드에 박힌 실제 값이고, "실측"으로 표시한 근거는 개발 중 실제 영상으로 확인한 것이다.

---

## 전체 흐름

```
원본 mp4 (100~225분)
   │
   ├─ 섹션1  ⓪-1 풀전사    원본 전체 STT → {품번}_원본전사.json/.srt
   │         ⓪-2 줄거리    그 전사로 요약 → {품번}_줄거리.md/.txt
   │                        (+ 사이트 소개문 교차 검증)
   │         ⓪-3 자르기    3중 필터로 부적절 구간을 물리적으로 잘라냄
   │                        → {품번}_클린.mp4   (보통 원본의 1~10%)
   │
   ├─ 섹션2  ① 전사        클린본을 일본어 STT
   │         ② AI          LLM이 컷 구간 + 한글 대사 + 내레이션을 한 번에 출력
   │         ③ 자막        keep 기준으로 시간 재계산 → SRT/JSON
   │                        → {품번}_final.mp4  (약 2분)
   │
   ├─ 섹션3  ① 내레이션    최종 영상 길이 기준으로 대본 재작성
   │         ② 배너        인포카드/워터마크 PNG
   │         ③ TTS         voicebox 음성 합성
   │         ④ 번인        1080p 리프레임 + 하드섭
   │                        → {품번}_final_subbed.mp4 (편별 납품본)
   │
   └─ 섹션4  ① 인트로 TTS  후킹 대본 6줄 → 문장별 wav + 실측 타이밍
             ② 컴포지션    HyperFrames(HTML+GSAP) 생성 — 화면이 말을 따라감
             ③ 렌더        인트로.mp4
             ④ 합본        인트로 + 12편(꼴찌→1위) concat
                            → _통합_{배치}.mp4 (업로드본)
```

**핵심 설계 원칙**: 섹션1에서 부적절 구간을 *물리적으로 잘라낸다*. 이후 모든 단계는 클린본만 보므로, 노출이 뒤 단계로 새어나갈 여지 자체가 없다. 부수 효과로 전사·AI가 다룰 길이가 1/10로 줄어 전체가 훨씬 빨라진다.

## 섹션1 — ⓪ 클린 (`stage_clean` → `_chain_clean`)

### 3단계 구조 (2026-09-07 재구성)

| 단계 | 하는 일 | 산출물 |
|---|---|---|
| **⓪-1 풀전사** | 원본 **전체**를 `scan_model`(small)로 STT | `_원본전사.json` / `.srt` |
| **⓪-2 줄거리** | 그 전사로 전체 줄거리 요약 + 사이트 소개문 교차 검증 | `_줄거리.md` / `.txt` |
| **⓪-3 자르기** | 3중 필터 순차 절단 (2️⃣소리 → 3️⃣의미 → 1️⃣화면) | `_클린.mp4` |

**왜 전사를 앞으로 뺐나.** 예전에는 이 전사가 2️⃣ 소리 필터 **안에** 숨어 있었다. 필터의 부산물일 뿐 산출물이 아니어서, 원본에 무슨 내용이 있었는지 아무도 모른 채 99%가 잘려나가는 일이 생겼다(ABF-382: 101분 → 1.6분).

전사를 독립 단계로 올리면:
- 원본 내용이 **항상 파일로 남는다**
- **자르기 전에** 줄거리를 세워 사람이 확인할 수 있다
- 소개문과 어긋나면 자르기 전에 경고가 뜬다

**비용 증가는 0이다.** 2️⃣ 소리 필터가 ⓪-1의 전사본을 그대로 받아 쓰므로(`scan_audio(segs=…)`) 전사는 한 번뿐이다.

`stage_clean`은 **클린본이 이미 있어도** 풀전사·줄거리가 없으면 그것만 채운다 — 다시 자르지 않는다.

### 왜 3중 필터인가

단일 판정기로는 전부 뚫린다. 각자 못 보는 것이 다르다.

| 필터 | 보는 것 | 놓치는 것 |
|---|---|---|
| 1️⃣ 화면 (NudeNet) | 노출 부위 | 옷 입은 채 어두운 조명 애무 (EXPOSED 0) |
| 2️⃣ 소리 (Whisper) | 대사 유무 | 무음의 노출 장면 |
| 3️⃣ 의미 (CLIP) | 장면의 뜻 | 미세한 부위 노출 |

셋을 순차로 걸면 서로의 사각지대를 메운다. 특히 **NN이 정사로 오판하던 "노출 의상으로 식사하며 대화하는 39분"을 2️⃣ 소리가 되살린다**(실측: FNS-235의 84~123분이 전부 "이거 진짜 맛있어" "새우 좋아해?" 하는 식사 대화였다).

### 왜 소리 → 의미 → 화면 순서인가

분당 스캔 비용이 다르기 때문이다.

| 순서 | 필터 | 분당 비용 |
|---|---|---|
| 1번째 | 2️⃣ 소리 (STT) | 0.69초 |
| 2번째 | 3️⃣ 의미 (CLIP) | 1.06초 |
| 3번째 | 1️⃣ 화면 (NN) | 1.44초 |

**제일 싼 스캔에게 제일 긴 영상을 맡기고, 제일 비싼 NN은 마지막에 남은 몇 분만 보게 한다.** 각 단계는 스캔 → 검출되면 그 자리에서 컷 → 잘린 영상으로 다음 스캔. 실측(123분 원본): 총 6분 32초 → **2분 3초**.

### 2️⃣ 소리 — 신음·정사 구간 (`moan.scan_audio`)

**판정 규칙: 내용 있는 대사가 있으면 정사가 아니다.**

- 정사신 = 신음·흥분 감탄만 있고 내용 있는 대사가 없다
- 대화신 = 짧든 길든 실제 대사가 촘촘히 오간다

그래서 화면이 아니라 **소리**로 판정한다. small 모델이면 2시간이 1~2분.

#### 약한 발화 판정 (`is_weak`)

아래 중 하나라도 걸리면 "보호 버블을 만들지 못하는 발화"다. 삭제 트리거가 아니라 *보호를 못 할 뿐*이며, 주변에 강한 대사가 있으면 그 버블 안에서 같이 살아남는다.

1. 모음·ん·장음·기호만으로 된 줄 (`ああああ`, `んー…`)
2. 8자 이하인데 신음 상용구 포함 — `イク` `いっちゃ` `気持ちい` `だめ` `やば` `あん` `はぁ` `んん`
3. 같은 문자 반복 (3자 이상인데 서로 다른 문자가 2종 이하)
4. 같은 토큰이 절반 이상 반복 (`やばい、やばい、やばい`)
5. 모든 토큰이 흥분 상용구이거나 2자 이하 — `やば` `だめ` `いい` `すご` `気持ち` `イク` `でる` `もっと` `やろう` `うそ` `ほんと` `エロ` `待って` `動いて` 등
6. 4자 이하 짧은 호명 (`トミー`, `うん`)

#### 대사 버블 방식

```
강한 대사 ──[ ±5초 보호 버블 ]── 강한 대사 ──[ ±5초 ]──
                                                        ↑
                        보호 밖 공백이 8초 이상이면 ─── 삭제 후보
```

- 보호 반경 `cut_pad_moan` = **5.0초** (강한 대사 앞뒤)
- 최소 삭제 길이 `min_len` = **8.0초**
- 근접 병합 `merge_gap` = **8.0초** (사이의 짧은 보호 조각은 남겨봐야 컷만 파편화됨)

대화신은 대사가 촘촘해 버블이 이어지므로 안 잘리고(식사 대화 0컷 실측), 정사신은 대사가 성겨서 뚫린다. 영상 시작·끝 공백도 똑같이 잡는다.

#### 폐기된 방식 — 30초 윈도우

"윈도우에 실대사가 하나라도 있으면 통째 보존" 규칙은 두 군데서 뚫렸다:
- 윈도우 경계에 걸친 **무대사 정사 43초**가 통과 (양옆 윈도우에 대사가 있었음)
- 어두운 조명의 옷 입은 애무씬이 **속삭임 몇 줄로 89초 전체를 지킴**

→ 대사 버블 방식으로 교체 (2026-07-13)

#### 배치 전사 금지

`BatchedInferencePipeline`은 세그먼트를 뭉쳐버린다. 실측(같은 120초): 순차 42세그 vs **배치 3세그**(45초짜리 덩어리). 텍스트는 살아도 타임스탬프가 뭉개져 "대사가 있는 시각"을 알 수 없고, 대사 있는 구간을 "대사 없음"으로 오판해 **123분 중 102분을 삭제**했다. 여기서는 시각 정확도가 전부이므로 순차 전사만 쓴다.

### 3️⃣ 의미 — 스킨십·애무 (`intimacy.scan_intimacy`)

NN과 STT 둘 다 못 잡는 사각지대를 메운다. 어두운 조명에서 옷을 입은 채 진행되는 애무씬은
- NN: 노출 부위가 없어 EXPOSED 0 → **완전 사각**
- STT: `動いていい?` 같은 속삭임이 **보호 버블을 만들어버림**

CLIP은 부위·대사가 아니라 **장면의 의미**를 본다.

#### 방식

```
프레임 (2초 간격, 320px)
   → CLIP 이미지 임베딩
   → 스킨십 프롬프트 7개 vs 일상 프롬프트와 코사인 유사도
   → margin = (스킨십 유사도) − (일상 유사도)
   → 14초 이동평균 스무딩
   → margin ≥ 0.02 가 14초 이상 지속되면 스킨십 구간
```

| 파라미터 | 값 | config 키 |
|---|---|---|
| 샘플 간격 | 2.0초 | `intimacy_step` |
| 임계 margin | 0.02 | `intimacy_threshold` |
| 최소 지속 | 14.0초 | `intimacy_min_dur` |
| 스무딩 폭 | 14.0초 | `SMOOTH_SEC` (코드 상수) |

**'지속' 조건이 핵심이다.** 파티 장면의 1~2프레임 스파이크(쓰러진 사람 부축 등)는 고립돼 있어 걸러지고, 애무는 수십 초 이어진다.

#### 프롬프트

- 잡는 쪽: `two people kissing passionately` / `a couple making out on a couch` / `a man and a woman being sexually intimate` / `a man touching and groping a woman's body` / `foreplay scene, caressing and undressing` / `people having sex` / `a couple embracing closely in a dim room`
- 놓아주는 쪽: `people sitting and talking at a party` / `friends eating and drinking at a table` / `a woman being interviewed` / `a person standing in a room talking`

일상 프롬프트에 **노출 의상 파티, 인터뷰**를 명시적으로 넣은 게 중요하다. margin 방식이라 이쪽이 이기면 통과한다. (softmax 확률 방식은 노출 의상 파티 장면까지 다 끌어올려 실패했다.)

#### 모델

`Xenova/clip-vit-base-patch32` ONNX 양자화 (vision 85M + text 62M). onnxruntime CPU로 26fps — 2시간 영상 약 2.5분. **완전 로컬, 프레임 외부 유출 없음.** `models/clip/`에 없으면 최초 1회 HuggingFace에서 자동 다운로드(~150MB).

검증(step2_stt.mp4 정답지): 애무 158~238초를 한 스팬으로 검출, 식사 대화 오탐 0.

### 1️⃣ 화면 — NN 노출 (`nsfw.build_map`)

| 파라미터 | 클린 단계 값 | config 키 |
|---|---|---|
| 샘플 간격 | 1.0초 | `nsfw_scan_step` |
| 임계 점수 | **0.22** | `nsfw_clean_threshold` |
| 앞뒤 여유 | 3.0초 | `nsfw_pad` |
| 근접 병합 | 12.0초 | `nsfw_merge_gap` |
| 최소 잔여 조각 | 3.0초 | `nsfw_min_clip` |

임계 0.22는 기본값 0.35보다 **공격적**이다 — 클린 단계에서는 경계선까지 잡아내는 쪽이 맞다.

#### 규칙 1 — 직접 노출

이 5종이 잡히면 그 프레임은 무조건 노출:
`FEMALE_BREAST_EXPOSED` `FEMALE_GENITALIA_EXPOSED` `MALE_GENITALIA_EXPOSED` `ANUS_EXPOSED` `BUTTOCKS_EXPOSED`

#### 규칙 2 — 정사신 윈도우 판정 (NN의 최대 구멍 메우기)

NudeNet은 '부위 노출'만 보고 '정사 행위'는 모른다. 각도·체위·이불로 부위가 가려지면 EXPOSED가 안 뜨고 COVERED로 분류돼 통과한다. **실측: 정사신이 남은 클린본에서 `BREAST_COVERED` 272프레임 vs `EXPOSED` 2프레임.**

그런데 `BREAST_COVERED`는 옷 입은 대화 장면에서도 100% 뜨므로 신호로 못 쓴다. 쓸 수 있는 신호는 **살 노출의 지속 비율**이다 — 옷을 벗었다는 뜻이라, 실측에서 정사 구간만 45~100%로 치솟고 대화 구간은 0%였다.

```
20초 창(SKIN_WINDOW) 안에서
ARMPITS_EXPOSED / BELLY_EXPOSED 프레임 비율이
30%(SKIN_RATIO) 이상이면 → 그 창 전체를 정사 구간으로 판정
```

#### 규칙 3 — 엄격 모드 (속옷 노출)

`FEMALE_GENITALIA_COVERED` ≥ 0.30 **하나만** 쓴다.

두 클래스는 시도했다가 **제외**했다:
- `BUTTOCKS_COVERED` — 바지·치마 입은 엉덩이가 프레임에 들어오기만 해도 뜬다. 정장 차림 현관 대화에서 0.61까지 나와 66프레임 오탐 (FNS-248 36~70초, 눈검사로는 완전히 깨끗한 구간)
- `FEMALE_BREAST_COVERED` (크롭탑·노출 상의) — 점수로도 개수로도 안 갈린다. 눈검사로 합격시킨 납품본 11편에 '2개 이상' 규칙을 돌려보니 **143프레임 / 7편**을 잡았다(검은 니트 인터뷰 38, 얼굴 클로즈업 57 — 전부 오탐)

→ **노출 의상은 자동 판정을 포기하고 몽타주 눈검사에 맡긴다.**

### 컷 방식

`cut_video_smart` — 경계 GOP만 재인코딩하고 중간은 스트림 카피. 경계 정밀도는 재인코딩 컷과 같은 frame-accurate라 노출 경계가 밀리지 않는다.

3중 필터는 단계마다 '남기는 분량 전체'를 다시 인코딩해 왔는데, 실측(ja14 FNS-230, 171분)에서 편당 66분 중 60분이 컷이었다(누적 재인코딩 119분). 남길 게 많을수록 손해라 스마트 컷을 쓴다.

폴백은 **재인코딩만**. `cut_video_copy`는 keep 시작을 앞쪽 키프레임으로 스냅해 직전 제거 구간(=노출)의 꼬리를 도로 물고 올 수 있어 클린 단계엔 부적합하다.

## 섹션2 — 리뷰 생성 (`rank_review.py`)

### ① 전사 (`stage_transcribe`)

`two_pass`(기본 on)면 `scan_model`(small)로 **러프 스캔만** 한다. 구간 선정용이다. 최종 대사 자막은 ②에서 keep 구간만 정밀 재전사한다 — 2시간 원본도 정밀 전사는 keep 합계(1~3분)에만 들어가므로 전체가 수 분에 끝난다.

10분당 1줄 미만이면 "대사 없는 본편형" 조기 경보를 띄운다.

### ⓪ 전체 줄거리 — 섹션1에서 이미 만들어 둔 것을 쓴다 (`story_brief`)

**문제**: 섹션2는 클린본만 본다. 클린이 공격적일수록 LLM이 보는 것은 원본의 몇 %뿐이라, 이야기의 앞뒤가 사라진 채 요약·컷선정·내레이션을 하게 된다.

> **실측 ABF-382** — 원본 101분 전사 179세그(그중 **내용 대사 104줄**) → 클린본 1.6분.
> 섹션2가 보는 것은 그중 15~20줄. 나머지 84줄은 존재조차 모른다.

**해결**: 섹션1 ⓪-2에서 이미 만들어 둔 `{품번}_줄거리.txt`를 그대로 쓴다. 없으면(구버전 작업 폴더) 여기서 만든다 — `_원본전사.json`이 있으면 그것으로, 그것도 없으면 `source_video`로 한 번 전사해서.

줄거리는 원본 전사본을 LLM에 통째로 보내 만든다:

```json
{"story": ["0분 — 대기실. 동료가 손님 선물을 자랑하고…"],
 "cast":  ["미야지마 메이 — 임자 있는 남자만 골라 흔드는 주인공"],
 "turns": ["6분쯤 — 휴대폰 화면을 들이밀며 판을 뒤집는다"],
 "hooks": ["'뭐든 할게, 진짜 뭐든' — 큰소리치던 남자가 3분 만에 애원하는 쪽이 된다"]}
```

#### 사이트 소개문과 교차 검증

전사만 보고 쓴 줄거리는 STT 오인식·화자 혼동으로 엉뚱한 이야기가 될 수 있다. 판매 사이트 소개문(`ja21/21.txt` 또는 메타 API의 `description`)은 **사람이 쓴 독립 근거**이므로, 둘을 맞춰 보면 전사를 잘못 읽었는지 값싸게 알아낼 수 있다.

같은 LLM 호출 안에서 판정까지 받는다:

| 판정 | 뜻 | 다음 |
|---|---|---|
| `일치` | 핵심 설정이 같다 | 그대로 사용 |
| `부분일치` | 큰 틀은 맞으나 세부가 다르다 | 그대로 쓰되 판정을 프롬프트에 같이 넘긴다 |
| `불일치` | 다른 이야기로 보인다 | 경고 + 작업로그 기록. 사람이 확인 |

판정과 근거는 **프롬프트에도 같이 들어간다** — 어긋난다는 걸 알면 LLM이 더 신중해진다. 작업로그에도 남는다.

#### 남는 파일 두 개

| 파일 | 용도 |
|---|---|
| **`{품번}_줄거리.md`** | **사람이 읽는 요약.** 판정 표 + 사이트 소개문 원문 + 줄거리·등장인물·전환점·후킹 후보 |
| `{품번}_줄거리.txt` | 프롬프트에 실제로 주입되는 텍스트 (캐시) |

캐시가 있으면 재실행 때 다시 만들지 않는다.

- 원본 전사본이 없는 구버전 작업 폴더면 `source_video`로 한 번만 전사해 만든다(small, 100분 ≈ 1~2분)
- 원본 대사가 8줄 미만이면 생략한다(대사 없는 본편형)
- 표현 규칙: 성적 묘사 없이 **상황·감정·관계·긴장만** — 이 텍스트가 그대로 프롬프트에 들어가고 최종 내레이션의 근거가 되므로

### ② AI (`stage_ai`)

#### 목표 길이 결정 (2026-09-07 변경)

```
target = min(config target_sec(120), 클린본 길이)
클린본 < 25초 → 여기서 중단
```

예전에는 클린본 길이와 무관하게 120초를 목표로 잡았다. 클린본이 7초로 붕괴한 편(ja20 SNOS-360)이 그대로 납품까지 갔고, 클린본이 짧은 편은 못 채울 목표 기준으로 내레이션 분량이 잡혀 영상에 안 들어갔다.

#### 전사가 길면 map-reduce

전사가 `map_reduce_chars`(25,000자)를 넘으면 20분 블록별로 '줄거리 + 핵심 대사 후보'만 뽑아 최종 선정 프롬프트 입력을 항상 작게 고정한다.

#### 화면 시각정보 (`visual_brief`)

클린본 프레임을 비전 모델이 읽어 '장면/화면글자' 브리핑을 만들고 프롬프트에 넣는다. LLM이 오디오 자막만이 아니라 **화면 행동·표정·소품**까지 알고 대사/내레이션을 쓴다.

#### LLM 원샷

`fullauto_mode`가 `highlight`면 `prompt_highlight` — "고루 분포"가 아니라 **후킹 밀도가 가장 높은 순간에 집중**한다.

- 각 컷에 `hook` 1~5점과 `reason` 한 줄을 매긴다
- 점수 높은 컷부터 채워 합계 target ±20% 목표
- **`hook_floor`(3) 미만인 컷은 목표 길이를 못 채워도 절대 안 넣는다** — 분량 메꾸려고 늘어지는 컷을 끼우면 실패. target보다 짧게 끝나는 편이 낫다

출력은 JSON 한 덩어리:
```json
{"summary":"...", "stars":1-5,
 "picks":[{"start":초,"end":초,"hook":1-5,"reason":"..."}],
 "keep":[[시작,끝],...],
 "dialogue":[{"start":초,"end":초,"ko":"...","speaker":"여|남"}],
 "narration":[{"start":초,"end":초,"text":"...","style":"기본"}]}
```

**프롬프트는 반드시 stdin으로 넘긴다.** argv로 주면 긴 자막이 잘려서 모델이 "자막을 보내주세요"라는 헛응답을 한다.

#### 안전 필터 (순서가 중요)

1. `_guard_keep` — 전사 대사가 0줄인 keep은 노출 장면 의심으로 제외
2. `snap_keep_to_lines` — 컷 경계를 대사 줄 경계로 스냅 + 앞뒤 0.15초 패딩 (말 중간에 끊기는 "…했습ㄴ" 방지)
3. 2차 정밀 재전사 — keep 구간만 large-v3로. **`initial_prompt`를 주지 않는다**: 메타 힌트가 배우 이름으로 끝나는데 whisper가 그 이름을 그대로 받아적어 구간 전체를 이름 한 줄로 뭉갠다(SNOS-334: 22줄 → 6줄)
4. 대사 번역 — 출력을 입력 정밀 전사와 시각으로 대조해 **빠진 줄만 최대 2회 재요청**(2026-09-07 추가). 예전엔 "모든 줄을 빠짐없이"라는 지시만 있고 검증이 없어 커버리지가 51~77%까지 떨어졌다
5. 비주얼 노출 가드 — 노출 지도로 keep에서 노출만 도려낸다(구간 통째로 버리지 않음)
6. `min_keep_ratio`(0.5) 미달이면 중단

**컷을 먼저 하고 성공한 뒤에 plan.json을 쓴다.** 완료 판정이 plan.json 존재로 되므로, 반대 순서면 컷이 실패해도 'AI 완료'로 오판된다.

### ③ 자막 (`stage_subs`)

LLM이 준 시간은 *원본 기준*이라 `retime(keep)`으로 **최종 영상 기준**으로 변환한다. keep 밖 항목은 버려진다.

- 대사: 24자 분할, `{품번}_대사.srt` + `.json`(화자 포함)
- 내레이션: **분할 안 함**(완결문장이라 끊으면 시간이 겹침), `{품번}_내레이션.srt` + `.json`
- `style="드립"`(구타바리 괄호자막)은 SRT에서 제외 — SRT는 TTS 입력이라 남기면 성우가 "(지림)"을 읽는다

마지막에 `ensure_narration` — 내레이션이 최종 영상 길이 기준 목표의 70% 미만이면 자동으로 다시 짠다(2026-09-07 추가).

## 섹션3 — 최종 생산 (`rank_produce.py`)

### ① 내레이션 재생성 (`regen_narration`)

섹션2의 내레이션은 **초안**이다. 그 뒤 노출 가드·눈검사 재컷으로 keep이 깎이면 `retime`이 밖으로 나간 항목을 버려서, 인트로만 남거나 반대로 인트로가 통째로 날아간다(ja20 START-627: 5줄 → 2줄, 98초 영상에 50초·90초 두 줄뿐).

여기서 **컷이 확정된 최종 영상 길이 기준**으로 통째로 다시 쓴다.

#### 밀도 규칙 (단일 기준)

```
줄 수 = clamp(영상초 / 15, 5, 10)
```

프롬프트 예산(`narration_budget`)과 재생성 슬롯(`narration_slots`)이 **같은 함수**를 쓴다. 예전엔 프롬프트가 98초 영상에 "17~20문장"을 요구하고 재생성기는 7줄을 원해 3배 어긋나 있었다(2026-09-07 통합).

촘촘하게 채우면 쓸 말이 떨어져 같은 소재를 반복한다(ADN-795: 14줄 중 4줄이 '웃음기/표정/얼굴/미소'). 벤치마킹 대상인 휴지도둑(120만 조회)도 '전환점만' 짚는 저밀도다.

#### 슬롯 구성

줄 수에 따라 역할이 정해진다:

| 줄 수 | 구성 |
|---|---|
| 3 | 소개컨셉 → 장면 → 마무리 |
| 5~6 | 소개배우 → 컨셉 → 장면×2~3 → 마무리 |
| 7+ | 소개 → 배우 → 컨셉 → 장면×N → 마무리 |

#### 배치 (2026-09-07 변경)

문체에 따라 다르다.

- **3min(딸감별사) / gootabari**: 최종 시간축을 줄 수만큼 등분해 **구획마다 한 자리씩**. 구획 안에 대사 없는 틈이 있으면 그 틈을 우선하고, 없으면 그냥 놓는다. 이 문체는 내레이션이 주 오디오이고 원음은 더킹되므로 대사 위에 얹혀도 된다.
- **cinema(고몽·김시선형)**: 대사 원음을 들려주는 게 핵심이라 **대사 없는 틈에만** 놓는다.

예전엔 문체와 무관하게 '대사 회피'만 했다. 대사가 영상의 67%를 덮는 하이라이트에서 쓸 틈이 3개뿐이라 내레이션이 한쪽으로 뭉쳤다(START-627: 0~6초에 2줄, 45초 공백, 마지막 11초에 4줄).

#### 글자수

슬롯 길이와 글자수는 **한 쌍**이다. voicebox 실측 발화속도 7.5자/초(`NAR_CPS`) 기준으로 `글자수 ≈ 슬롯초 × 7.5`를 넘으면 TTS가 슬롯을 넘겨 대사를 덮는다. 절대 상한 30자(`NAR_MAX_CHARS`).

#### 서수 인트로

`seq=(i, n)`을 받아 "n편 중 i번째"를 안다 → "세 번째 작품은 미야지마 메이입니다". **랭킹 순서대로 돌려야 서수가 맞는다.** 제외분은 seq를 세기 전에 걸러낸다.

### ② 배너 (`stage_banner` → `gen_infocard`)

품번 → DB 메타 조회 → 투명 PNG 3장(프레임 / 인포카드 / 워터마크).

- 3사이즈 없으면 **중단**(스펙 빠진 카드가 납품되면 안 됨)
- 메타 자체가 없으면(아직 크롤링 전인 신작) **배너만 생략**하고 자막·TTS·번인은 진행

### ③ TTS (`stage_tts` → voicebox)

문장별로 wav 생성. `tts_candidates`(3)개를 seed를 바꿔 만들고 **resemblyzer로 기준 임베딩(`voice_ref.npy`)에 가장 가까운 것을 채택**한다 — voicebox 생성 편차(실측 0.71~0.97) 때문에 문장 하나가 다른 목소리처럼 들리는 것을 막는다.

#### 트랙 합성 (`build_narration_wav`)

TTS 실제 발화가 슬롯보다 길면:
1. `atempo`로 살짝 빠르게 — 최대 **1.12배**(말투 보존 우선)
2. 그래도 넘치면 다음 문장 시작을 **뒤로 민다** (싱크가 밀려도 두 목소리가 겹치는 것보단 낫다)
3. 그 결과 내레이션이 영상보다 길어지면 상한을 **1.35배**로 올려 재계산 (아웃트로가 잘리는 것보단 조금 빠른 말투가 낫다)

목소리가 실제로 나는 구간(`spans`)을 돌려줘서 원음 더킹을 그 구간에만 정확히 건다.

### ④ 번인 (`stage_burn`)

1. **1080p 리프레임 먼저** — 위쪽 중앙 200% 확대. 720p에 자막을 굽고 나중에 확대하면 글자가 같이 뭉개진다. 먼저 1920×1080으로 만들어야 자막·배너가 native 해상도로 들어간다
2. 자막 스타일 1.5배 스케일 (720p 캔버스 기준이라 그대로 쓰면 글자가 절반으로 보임)
3. ASS 하드섭 — **대사 자막 + 배너/워터마크만**. 내레이션 SRT/JSON은 잠시 숨긴다(납품 규격상 내레이션은 사람이 따로 얹는다)
4. 완성본 전수 검사(NudeNet) + 자체 검사 + `_완성`/`_검수필요` 폴더로 수거

## 섹션4 — 통합 영상 인트로 (`tools/section4_intro.py`)

섹션3까지는 **편별** 납품본을 만든다. 섹션4는 그 12편을 **한 편의 랭킹 영상**으로 묶기
위한 앞머리(후킹 인트로)를 만들고 이어붙인다.

### 왜 별도 섹션인가

편별 파이프라인과 입력·산출물·실패 모드가 전혀 다르다. 섹션3은 `{품번}` 폴더 하나를
보지만 섹션4는 **배치 전체**(랭킹 txt + 12편의 인포카드·완성본)를 본다. 섹션3 도구에
끼워 넣으면 편별 재실행 때마다 인트로가 딸려 다시 만들어진다.

### 대본이 진실의 원천

`section4/멘트.txt` — 배치 폴더에 `_인트로/멘트.txt` 가 있으면 그쪽이 우선.
문구는 LLM이 쓰지 않는다. **사람이 확정한 문장을 그대로 읽는다.**

ja21 기준 6줄 — 후킹 장치는 `벤치마킹/README.md`(골채널 4곳 자막 분석)와
브런치 「훅 카피 유형 12가지」에서 가져왔다:

| # | 멘트 | 장치 |
|---|---|---|
| 1 | 9월 첫 주 신작 500편, 전체 다 보다가 눈도 빠지고 다른 것도 빠질 뻔했습니다. | 투자한 자원 강조 + 1인칭 몸 리액션 |
| 2 | 여러분들의 추천 수, 좋아요, 싫어요, 조회수를 가지고 뽑은 최고의 12편. | 권위 이양(내 취향 아님을 숫자로) |
| 3 | 특히 이번 주 1위는 좋아요가 46에 싫어요는 딱 1개네요. 싫어요 한 분 누구죠? | 충격 수치 + 셀프 츳코미 |
| 4 | 12위부터 1위까지 빠르게 갑니다. | 구조 예고 |
| 5 | 끝까지 시청해 주세요. | 이탈 방지 CTA |
| 6 | 먼저 12위입니다. | 본편 연결 |

★**TTS 표기 정규화만 손댄다**: `12위붜`→`12위부터`, `누구져`→`누구죠`
(voicebox가 "져"를 [저]로 읽는다). 뜻이 바뀌는 수정은 하지 않는다.

### ① TTS (`tts`)

섹션3과 **같은 프로필·시드·후보 3개**로 문장별 wav를 만든다(목소리가 본편과 달라지면
안 된다). 만든 뒤 ffprobe로 **실측 길이**를 재서 `_인트로/lines.json`에 적는다.

★배치 TTS가 도는 중에는 돌리지 말 것 — voicebox 큐가 하나라 600초 타임아웃을 부른다.

### ② 컴포지션 (`build`)

`lines.json`의 실측 타이밍으로 6줄 = 6씬을 배치한다. lines.json이 없으면 자수 추정
(6.2자/초)으로 만들고 경고한다 — **TTS 후 다시 build 해야 화면이 말과 맞는다.**

| 씬 | 화면 | 자산 |
|---|---|---|
| 1 | 미리보기 난사 + 카운터 `0 → 500` + 흰 플래시 | `{품번}_미리보기_애니.mp4` ×12 |
| 2 | 인포카드 6×2 그리드 착지 + 좋아요/싫어요/조회수 집계 | `{품번}_인포카드.png` ×12 |
| 3 | 1위 카드 블러 + `?` + `46 : 1` 스코어보드 | 1위 인포카드 |
| 4 | 숫자 `12 → 1` 러시 | — |
| 5 | CTA | — |
| 6 | 꼴찌 카드 상승 → 페이드 → 본편 | 12위 인포카드 |

집계 숫자(좋아요·싫어요·조회수)는 랭킹 txt에서 `_ranklist.load_details`로 뽑는다.
1번 줄의 `500`만 외부 값이라 `--pool` 인자로 받는다(주간 신작 총량 — 로컬 DB로는 못 센다).

### ③④ 렌더·합본 (`render`, `merge`)

`npx hyperframes render` → `_인트로/인트로.mp4`.
`merge`는 인트로 + `_완성/` 12편을 **꼴찌 → 1위** 순으로 concat 해서
`_통합_{배치}.mp4` 를 만든다. `_완성`에 없는 편(노출 격리분)은 건너뛰고 경고한다.

### HyperFrames 함정 (실측으로 걸린 것)

| 증상 | 원인 | 대응 |
|---|---|---|
| 자막이 안 보임 | 캡션에 z-index가 없어 씬 시트(z 13~17) 아래로 깔림 | `.cap { z-index:90 }` |
| 첫 프레임 백지 | 전체화면 시트가 기본 노출 상태 | `.sheet{opacity:0}` + `to(opacity:1)` 등장 |
| 글자가 폴백 폰트로 | Noto Sans KR이 렌더러 자동 폰트 목록에 없음 | `@font-face { src: local('Malgun Gothic') }` |
| 영상 위 핑크 글자 2.64:1 | 그림자만으로는 WCAG 3:1 미달 | 어두운 판 + 영상용 밝은 핑크(`#ff5c7d`) 분리 |
| 그리드가 자막을 침범 | 4열 3행이라 세로로 큼 | 6열 2행 + 시트 하단 패딩 215px |

검증은 `npx hyperframes check` — lint(구조) + motion + layout + contrast를 한 번에 본다.

### 폴더 정리 (`tools/organize_out.py`)

품번 폴더에 파일이 25개쯤 평면으로 쌓이면 무엇이 어느 단계 결과인지 알 수 없다. 이 도구가 **원본을 건드리지 않고** 하드링크로 단계별 트리를 세운다 — 디스크 추가 사용량 0.

## 랭킹 순서 (ja21~)

소스 폴더의 랭킹 txt(`ja21/21.txt`)가 **진실의 원천**이다. 게재 순서가 곧 순위이고, 이 순서가 섹션3의 서수 인트로("세 번째 작품은…")를 결정한다.

```bash
# 섹션2 — 리뷰 생성 (랭킹순)
.venv\Scripts\python.exe tools\rank_review.py --src "C:\...\ja21" --out "F:\ja_reviewer_out\ja21"

# 섹션3 — 최종 생산 (랭킹순, 서수 자동)
.venv\Scripts\python.exe tools\rank_produce.py --src "C:\...\ja21" --out "F:\ja_reviewer_out\ja21"
```

ja20까지는 배치마다 `_review_rank_jaNN.py` 같은 파일을 복사해 랭킹을 코드에 하드코딩했다. ja21부터는 `tools/_ranklist.py`가 txt를 읽으므로 경로만 바꾸면 된다.
